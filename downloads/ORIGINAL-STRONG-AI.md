# 原版强 AI 派遣：天凤个室与雀魂友人房

本包直接使用你上传的强 AI 原始权重，不是 v5，也不是刚训练的新模型。权重不转换、不微调，在线对战不更新参数；模型菜单名称为「原版强 AI · 上传原权重」。

20261105.5 根据实际诊断修正庄家首打的发送时序、配牌摸切标记，以及换局确认 1204 时过早停止接收终局结果的问题，见 `HOTFIX-OPENING.md`。包含暗杠/加杠通知修复；原权重不变。已用匿名起手牌及模拟开局窗口回归，真实平台首打是否恢复仍需本机复测。

## 启动

1. 关闭旧控制台，把整个文件夹解压到较短的路径，例如 `C:\mahjong-ai`。不要在压缩包预览或临时解压目录里运行。
2. 已有 **64 位 Python 3.12** 可以继续用。双击 `start-original-ai.cmd`，首次会安装 CPU 推理依赖并检查权重和原生组件，之后打开邀请派遣网站。
3. 管理员入口为 `http://127.0.0.1:8780/admin`。首次设置管理员口令与用户邀请口令；然后在后台分别保存天凤登录 ID、雀魂账号及密码。
4. 用户入口为 `http://127.0.0.1:8780/`。用户凭邀请口令进入，选择天凤/雀魂、房间号和 1–3 个原版强 AI，然后派遣。每位 AI 必须使用不同账号。

账号由后台自动分配，用户看不到登录 ID 或密码。用户网站仅提供派遣与自己的任务进度。需要本机旧管理控制台时，运行 `start-ai-console.cmd`。

## 覆盖旧程序

先关闭旧进程，再覆盖本包同名程序文件，保留原来的 `dispatch-accounts.local.json`、`dispatch-site.local.json` 和历史任务。包内没有账号配置，不会附带或覆盖这些文件。

新依赖使用独立的 `.venv-original`，不会删除旧 `.venv`。原模型和旧模型的格式不同，不要只拿权重覆盖 v5 的 `.pt`；应使用完整新包。

## 支持范围与检查

- 天凤：四人三赤半庄个室。
- 雀魂：国服普通四人三赤半庄友人房，不支持特殊规则。
- 推理只读取自己的手牌和实际公开事件；服务器动作许可在推理前参与合法动作交集。
- 万、筒、索的赤五与普通五使用不同动作；立直后的切牌也按服务器具体的 `0m/5m`、`0p/5p`、`0s/5s` 候选处理。
- 庄家 14 张起手转换为原生协议所需的 13 张加首摸；诊断区分合成首摸与本人客户端的显示，后者不能从旁观手切标记推断。
- 单局和牌、流局不会直接结束整场任务；仅服务器的整场结果通知计为完成。

运行 `check-original-ai.cmd` 可生成不含账号密码的 `original-ai-check.json`。如果仍出现连接问题，可运行 `check-majsoul-network.cmd` 或从管理员任务中下载诊断。

Windows Python 3.12 原生组件由公开源码重新编译，**不会加载原压缩包中只能用于 Python 3.10 的组件**。原始权重 SHA-256：

`55e78deeca0a020a9b99578e936a27cafdacaa62072259e354571554a93322c9`

离线测试验证原始权重、合法动作转换、赤五立直、首打、换局、整场结束，以及与未增加平台约束的原生参考策略的完整半庄动作核对。测试不会登录真实账号；真实入房及完整平台对局仍需在你本机验证。更换模型不会自动修复本机网络或代理问题。

模型在运行网站的电脑上推理，仍使用那台电脑的网络。如果网站运行在云服务器，才改用云服务器的网络。本包不包含云服务器部署或购买。
